# `tsrslint`

[![npm](https://img.shields.io/npm/v/@maschwenk/tsrslint)](https://www.npmjs.com/package/@maschwenk/tsrslint)
[![license](https://img.shields.io/badge/license-MIT-blue)](https://github.com/maschwenk/tsrslint/blob/main/LICENSE)

`tsrslint` is a drop-in replacement for [tsgolint](https://github.com/oxc-project/tsgolint), the type-aware lint
backend of [oxlint](https://oxc.rs), written in Rust on top of [tsrs](https://github.com/maschwenk/tsrs).
It runs the same rules and reports the same diagnostics, faster and in a fraction of the memory.

## Get started

```sh
npm i -D oxlint @maschwenk/tsrslint
OXLINT_TSGOLINT_PATH="$(npx tsrslint-path)" npx oxlint --type-aware
```

oxlint runs the backend that `OXLINT_TSGOLINT_PATH` points at, and otherwise the `tsgolint` bin in `node_modules/.bin`.
tsrslint's bin is named `tsrslint` so it can sit next to `oxlint-tsgolint`; you opt in by pointing the variable at the
native binary, whose path `tsrslint-path` prints (`require("@maschwenk/tsrslint").binaryPath()` in Node). Binaries
ship for macOS arm64 and Linux x64 and arm64 (glibc). From source, `cargo build --release` builds
`target/release/tsgolint`. Packaging details: [npm/README.md](npm/README.md).

## Conformance

tsrslint ports all 61 tsgolint rules from tsgolint 7.0.2005's code, and everything around them: payload V1 and V2, file-to-tsconfig assignment, the inferred program for
unmatched files, tsconfig and `--type-check` diagnostics, source overrides, and `-fix` / `-fix-suggestions`.
Each rule runs tsgolint's own Go test cases, extracted to JSON, on every commit ([rule coverage](docs/rules.md)).

Our goal is output identical to stock tsgolint. The benchmark below compares every diagnostic of both binaries by
file, range, rule and message id. The few that differ come from TypeScript itself: tsrs ports TypeScript 7.1-dev
while tsgolint 7.0.2005 is built on TypeScript 7.0, so some printed types (union member order, elided members,
`typeof import("…")`) read differently, and a type that 7.0 and 7.1 check differently can change what a rule reports.

## Contributing

```sh
pnpm install --frozen-lockfile           # @types/node, needed by some no-deprecated cases
cargo test --release --test rule_tests   # every rule against tsgolint's extracted test cases
python3 tools/lint/ratchet.py && python3 tools/lint/source.py
```

The Rust port lives in `crates/tsrslint/`; the rest of the repository is tsgolint at v7.0.2005, kept as the porting
reference ([docs/porting.md](docs/porting.md)). [CI](.github/workflows/ci.yml) runs the commands above on every pull
request, along with `cargo fmt`, headless and npm smoke tests, and checks that the rule table, the benchmark table and
the charts are current. See the [security policy](.github/SECURITY.md) for reporting vulnerabilities.
