## Benchmark: tsrslint vs tsgolint 7.0.2005

Each row lints one open-source project with all 61 rules (default options) through tsgolint's headless protocol, the way `oxlint --type-aware` runs its backend, with stock tsgolint 7.0.2005 (npm `@oxlint-tsgolint/linux-x64@7.0.2005`) and with tsrslint at commit `7cec06124f4e` (the PGO `dist` build, built like the npm release binaries). Both get the same payload; median of 3 interleaved runs, on GitHub Actions `ubuntu-24.04` (4 vCPU, 16 GB RAM, Linux x86_64, AMD EPYC 9V74 80-Core Processor).

in PGO training: the release binaries' profile is trained on these files (`.github/scripts/pgo-train.sh`), which flatters tsrslint there; the other projects are held out. diagnostics: rule diagnostics each binary reports. same diagnostics: both report the same multiset of (file, range, rule, message id); a bold cell is a disagreement, and a few are expected: tsrslint ports tsgolint 7.0.2002's rule code and has not ported some fixes stock got since. When one binary's runs report different sets (multi-threaded nondeterminism), the closest pair is compared and the cell says by how many diagnostics that binary's runs differ. text differs: diagnostics both report whose message text differs; expected in small numbers, since tsrs ports TypeScript 7.1-dev and tsgolint 7.0.2005 is built on TypeScript 7.0, which print some types differently, and some messages changed upstream after 7.0.2002. wall: process wall-clock time. speedup: stock wall / tsrslint wall. peak RSS: maximum resident set size; memory below 1x = tsrslint uses less.

Runner: GitHub Actions `ubuntu-24.04` (4 vCPU, 16 GB RAM, Linux x86_64, AMD EPYC 9V74 80-Core Processor). Date: 2026-10-26 13:03 UTC. tsrslint commit: `7cec06124f4e`.
